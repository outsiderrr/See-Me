# Fathom 提炼提示词（正式版）

> 把这份文件整个交给你的 agentic AI（Codex / Claude / 任意有 shell 的助手）。
> 它是自足的：不需要任何本文件之外的背景知识。
> 管线里它的位置：`原始/`（素材）──本提示词──▶ `库/`（主题笔记）──`tools/import`──▶ 服务器。
> 提炼刻意不由代码调模型——契约是文件格式，零凭证依赖、零厂商锁定。
> 产物会被 `tools/import/import.mjs check` 独立校验，别指望"大概符合"能过。

## 任务

读数据湖里还没提炼过的原始素材，把**用户本人的想法**整理成能独立阅读、又能与同题内容连接的主题笔记，写进 `库/`。

- 数据湖：`~/通用空间/潜心/`
- 输入：`原始/语音备忘录/2026-Wnn/raw/*.md`、`原始/chatgpt/2026-Wnn/raw/**/*.md`、`原始/codex/2026-Wnn/raw/*.md`，以及已转成可读文本的 `原始/flomo/2026-Wnn/raw/*`
- 周报（`2026-Wnn.md`，在 raw/ 外面）只是索引摘要，**不提炼**
- 输出：`库/<覆盖的最新采集周>.md`（如 `2026-W30.md`），一批只写一个文件
- **幂等**：动手前先收集已有 `库/*.md` 里所有 `source:` 行——已经出现过的素材跳过，只提炼新的
- **已有的 `库/*.md` 是历史档案，绝不回头改**：改了标题会被导入器当成新记录、
  改了正文会被当成"有改动"丢弃——两种都不是你想要的。要修记录去找用户。

## 输入格式

**录音（voice）**：头部列表含录音日期、时长、源文件、转写方式；正文在 `## 自动转写正文`；
可选 `## 识别说明`。转写不确定处用方括号标注，如 `[结尾未完整说清。]`。

**对话（chat）**：头部列表含项目、项目内顺序、网页显示时间、对话链接；正文按
`## 第 N 条可见消息`（或 `## 第 N 轮`）分节，节内 `### 用户` / `### AI` 区分角色。
**这个角色区分是语义关键**：「用户」是本人表达，「AI」是外部内容。

## 什么算一条主题笔记

- **一条 = 一个完整的小论点**，而不是一个零散句子。同一主题下的前提、经历、修正和暂定结论应尽量合在一条里。
- 一份素材通常出 1~4 条；只有一个主线时就出 1 条。全程没有个人表达的素材出 0 条（在报告里说明）。
- `topic` = 稳定的主题名（4~18 字），如「交易中的机会成本」。不同素材谈的是同一问题时，必须复用同一个 `topic`，不要为了变换措辞新造近义主题。
- 标题 = 这条笔记的一句话主张（10~24 字）。正文通常 180~600 个中文字符、2~6 个短段落；材料本身很短时可以更短，不要为凑长度增加内容。
- 第一人称，保留「我」的口吻和语气。把同一论点的相关表达连成可读的完整段落，但不填补用户没有说过的因果。

## 观点归属与事实边界

- 用户直接表达的判断、经历、决定可以写入，但必须保留「可能」「我在想」「暂时」等探索性限定。
- 用户提问不等于用户认同问题中的命题；用户没反驳 AI 也不等于认领 AI 的观点。
- AI 只是忠实转写或命名时，可以使用其结构，但不能把 AI 的句子冒充成用户原话。AI 新增的解释、建议、事实或推论，只有在用户明确认领后才能按其认领范围写入。
- 未联网核验的外部事实不能写成已证实事实。若一条笔记无法避开，用「根据当时对话中尚未核验的信息」限定；不要自动联网搜索。

## 提炼红线

1. **只提炼用户本人的表达。** AI 的观点只有在用户明确表示认可时才能出现，
   且正文必须以「认可了……」开头，让读者知道这是外部观点的认领。
2. **方括号标注的不确定段，内容一个字都不能进产物**——也不要改写着用，整段绕开。
3. **书面化改写，但不虚构**：口语顺成书面语；具体数字、金额、事实原样保留；
   模糊的感受保持模糊（"非常模糊的感觉"就写"非常模糊的感觉"），不加分析、
   不下结论、不发明因果。
4. 原话本身已经凝练时可以保留原句，但**连续照抄别超过一两句**——校验器把连抄
   120 字判为错误（那是倾倒不是提炼）。
5. 产物里不许有：方括号（`[]`『【】』都不行）、链接、图片语法。
6. `dated` 从素材头部取（voice = 录音日期，chat = 网页显示时间里的日期）。
   **取不到就跳过该素材并在报告里说明——不要猜。**
7. `suggest` 0~2 个，只能用词表里的词——词表在湖里 `~/通用空间/潜心/.import-config.json`
   的 `tags` 字段（= 用户已有标签；刻意不写进这份公开文件）。拿不准就留空 `[]`。

## 输出格式（逐字段照抄模板）

```markdown
---
source: 语音备忘录/2026-W27/raw/01-北京路.md
kind: voice
dated: 2026-07-06
topic: 个人价值与选择
suggest: [私密, 价值观]
---

## 一句话标题

正文。
```

- `source`：相对 `原始/` 的路径（它是幂等判重的锚，一个字都不能错）
- `kind`：`voice` | `chat` | `memo`，必须与 source 的目录一致（flomo 用 `memo`）
- `topic`：结构化主题名，阅读端会把同主题的笔记放在一起
- 多条笔记首尾相接写进同一个文件
- 正文里**不要出现独占一行的 `---`**（会撞散记录流的结构）

## 写完必须自查

在仓库目录（`~/通用空间/fathom`）下跑：

```
node tools/import/import.mjs check ~/通用空间/潜心/库/<你写的文件>.md
```

修到 **0 错误**为止；每条警告人眼确认后在报告里说明。校验器会查：字段完整、
方括号残留、不确定段混入、成段照抄、链接、词表、条目重复、素材覆盖缺口。

## 最后交一份报告

素材数（含跳过的及原因）／笔记数／每条警告的确认结论／你拿不准的地方。
