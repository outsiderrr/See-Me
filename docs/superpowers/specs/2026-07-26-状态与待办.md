踩过的坑（同类问题的排查顺序）：域名买后要**实名认证**，未认证会被注册局
`clientHold`——表现为 DNS 完全解析不到、Caddy 拿不到证书、443 握手报
`tlsv1 alert internal error`。企业主体买的域名走企业实名（营业执照，持有者名称
必须与执照完全一致）。实名通过、DNS 生效后，**Caddy 仍在指数退避里不会立刻重试**，
要 `docker compose restart caddy` 才会马上重申证书。
另注：本机梯子 TUN 模式会把域名劫持成 `198.18.x.x` 假地址，排查时用
`curl --resolve` 直连真实 IP 才看得到真相。

以下是原始设计记录：

域名 `fathomlog.com` 已购得并过注册局审核。代码侧已合并：compose 加 caddy 服务

`NODE_ENV=production`（cookie secure 生效）、Caddy 整体替换 XFF（`clientIp.ts`
的信任前提成立，伪造头失效）。用户三步：DNS A 记录 → 防火墙放行 443 →
服务器 `git pull && docker compose up -d --build`，详见 `DEPLOY.md`「域名 + HTTPS」节。
部署后控制台一律 `https://fathomlog.com/console`，裸 IP 无人应答。以下留档：

## 4. 环境地雷（新会话必读，全是踩过的）

- **仓库在 iCloud 托管的 `~/Desktop` 里。** 今天修了两个由此而来的故障：清掉 457M Xcode 产物（`git status` 从卡死变 0.036s）；删掉 `.git/COMMIT_EDITMSG` 死空壳（它让 `git commit` 永久挂死）。**再遇 git 卡死，先找 `.git/` 里 `blocks=0` 的文件**：
  `find .git -type f -exec stat -f "%b %z %N" {} \; | awk '$1==0 && $2>0'`
- **`gh pr merge --delete-branch` 危险**：它触发的本地 checkout 曾以 `mmap 失败` 死在一半，把工作区文件删掉、`schema.prisma` 截成 0 字节。合并时**不要带 `--delete-branch`**，本地同步自己来。修复：`git restore --source=HEAD -- .`
- **push/fetch 要绕开死代理**：`git -c http.proxy= -c https.proxy= push`（`~/.gitconfig` 指着 127.0.0.1:33210，通常没在监听）
- **Claude 侧到服务器：HTTP 通（~240ms），SSH 不通。** 所以线上验证 Claude 自己能做，任何要 shell 的事必须用户跑。`~/.ssh/` 里只有 codetrade 那台机器的密钥
- **本机 curl 一律 `--noproxy '*'`**
- **本机没有任何 Claude API 凭证**：无 `ANTHROPIC_API_KEY`、无 `ant` profile、`claude` CLI 的 OAuth token 已过期。这正是 P4 改成「提示词交给用户的 AI」的现实原因之一
- **服务器目录仍是 `/opt/see-me`，刻意不改名**：Compose 从目录名派生项目名并用它做卷名前缀，改目录会让它找不到 `see-me_db-data` 而在**空库**上静默启动。compose 里已把 `name: see-me` 钉死，所以真要改也不会丢数据
